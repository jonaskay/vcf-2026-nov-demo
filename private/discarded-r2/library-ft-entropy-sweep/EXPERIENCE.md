## Transferable lesson

- **cue**: The fix will rewrite source text that some checked-in artifact quotes word for word or fingerprints, such as a security-scanner ignore list, a snapshot or a lint baseline. Tests do not run that artifact's check, so a green suite hides the drift.
- **lesson**: In the domain skill under skills/, name each such coupled artifact, the exact source lines it fingerprints, the command that rechecks it (for example `bin/brakeman`) and how to refresh the entry when a warning comes back, and add that command to the skill's done checklist. Then check that runs which change the coupled text run the command before they submit.
- **evidence**: SKILL.md row: after reading the skill at step 3, all 3 dom runs ran bin/brakeman, got exit 3 and updated config/brakeman.ignore (dom r1 step 27, dom r2 step 61, dom r3 step 55), and so did composed r2 step 42. None of the 3 base runs ran brakeman, and base r1 changed the fingerprinted where text and submitted at step 69 with a green suite.
- **confidence**: medium. The contrast is 3 of 3 against 0 of 3, from a candidate that changed only this component, and each run cites the skill's fact before acting. But the cue is narrow, and nothing here shows whether an outdated ignore entry would have broken anything later.
