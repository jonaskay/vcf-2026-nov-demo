## Transferable lesson

- **cue**: A domain skill gives the executor a full list of every site the requested state could touch (caches, etags, JSON, docs, surfaces that render it) and says to apply the change and prove it at each one, in a feature task run against a fixed wall-clock limit whose base runs already finish with time to spare.
- **lesson**: In skills/<domain>/SKILL.md, split every list of sites into "required by the request" and "optional, only if time remains". Do not use wording like "apply at every site above" or "prove it with a test" for sites the request does not name. Give a time-boxed exit, such as "after the full suite passes and less than ~20 min remain, submit". Check: every checklist item in the skill either traces to a phrase in the request or is marked optional.
- **evidence**: The skills/card-state-and-index/SKILL.md row was rated hurt. After reading its §5 "every cache/etag site", dom r1 spent steps 109-120 debugging one etag test and timed out at step 123. dom r3 swept fresh_when sites, jbuilders and docs from step 120 to step 147 and missed the submit. Base runs, which had no such checklist, finished 3/3 with 22-37-file patches, against 2/3 dom timeouts with 39-62-file patches. The skills/db-migration/SKILL.md row (helped) shows that a skill made of narrow, procedural facts does not inflate scope the same way.
- **confidence**: medium; the timeout and patch-size contrast holds across the whole dom set (3/3 patches larger, 2/3 timeouts) and ties to steps that follow §5, but only one skill shape was tested, and no variant with the checklist marked optional was run.
